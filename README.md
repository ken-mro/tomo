# 🍅 tomo — focus friend

A cute, polished **Pomodoro timer** web app whose little tomato mascot keeps you
company while you focus. tomo can pop a small **square floating window**
(Picture-in-Picture) so your timer stays visible even when the app is minimized
or in the background.

> _pomodoro_ = tomato 🍅 · _tomo_ = 友 ("friend" in Japanese) → your **focus friend**.

---

## Quick start

```bash
pnpm install
pnpm dev        # start the dev server (http://localhost:5173 by default)
pnpm build      # type-check + production build into dist/
pnpm preview    # preview the production build
```

> Uses **pnpm**. The built-in alarm sounds and the PWA icons are generated by
> `scripts/gen-sounds.mjs` and `scripts/gen-icons.mjs`, which run automatically
> before `dev`/`build` (`pnpm gen:assets` to regenerate, add `--force` to overwrite).

The output in `dist/` is fully static — drop it on any static host (no backend).

---

## Deploy to GitHub Pages

A workflow at `.github/workflows/deploy.yml` builds and publishes the app on every
push to `main`/`master` (and can be run manually from the Actions tab).

One-time setup: in your repo, go to **Settings → Pages → Build and deployment →
Source** and choose **GitHub Actions**.

The **base path is auto-detected** in `vite.config.ts` from `GITHUB_REPOSITORY`:
- **Project page** (`https://<user>.github.io/<repo>/`) → base becomes `/<repo>/`.
- **User/org page** (`https://<user>.github.io`, repo named `<user>.github.io`) → base `/`.
- **Local builds / other hosts** → relative `./`.

So the service worker scope, manifest, and asset URLs are all correct under the
subpath with **no manual configuration**. A `.nojekyll` file is included so Pages
serves every asset as-is.

> To deploy somewhere else (Netlify, Vercel, static bucket, etc.), just serve the
> `dist/` folder. If it's hosted under a subpath, build with that base, e.g.
> `GITHUB_REPOSITORY=x/your-subpath pnpm build` or add your own `--base=/path/`.

## Features

### Pomodoro technique
- **Work** (default 25 min), **Short break** (5 min), **Long break** (15 min).
- Long break after every **N** completed work sessions (configurable, default 4).
- Pomodoro-progress **dots** that fill in and reset after a long break, plus a
  **daily completed count**.
- A pomodoro only counts when its **full** work interval elapses — skipping or
  resetting never inflates the count.
- **Start / Pause / Resume**, **Reset** (current interval), **Skip** (work ↔ break),
  and **mode tabs** to switch Work / Short / Long at any time.
- The countdown is **timestamp-based** (`Date.now()` deltas), so it never drifts
  even if the tab is throttled in the background.

### Settings (persisted)
Durations, long-break interval, **auto-start breaks**, **auto-start next pomodoro**,
**volume**, and an optional **ticking sound** while working. Stored in
`localStorage`.

### Alarm sounds
- Four built-in, royalty-free **synthesized** sounds: **Bell, Digital, Chime, Gentle**.
- **Upload your own** audio file — stored in **IndexedDB** so it survives reloads.
- **Preview** button next to each sound; the volume slider applies to the alarm.

### Internationalization
- **English, 日本語, 中文 (Simplified), Español.**
- Every user-facing string lives in `src/locales/*.json` — nothing is hardcoded.
- The browser language is auto-detected on first load (closest supported locale,
  falling back to English) and your explicit choice is persisted.
- Adding **Traditional Chinese** is easy: ship a `zh-TW` resource and add it to
  `SUPPORTED_LANGUAGES` in `src/i18n.ts`.

### Look & feel
- Cute, minimal design with the tomato/peach palette, rounded **Fredoka** wordmark
  + **Quicksand** body font, soft shadows and generous whitespace.
- **Light / dark mode** with a manual toggle, defaulting to the OS preference and
  persisting your choice. Colors are CSS custom properties, so both themes — and
  the Work (tomato) / Break (leaf) mode tints — stay consistent, **including
  inside the PiP window**.
- The browser **tab title** shows the remaining time and mode (e.g. `24:13 — Work · tomo`).
- Keyboard-friendly: **Space** = start/pause.

### Installable PWA (offline-capable)
tomo is a **Progressive Web App** — you can install it to your home screen / dock
and run it offline:
- **Web app manifest** (`standalone` display, theme/background colors, productivity
  category) generated by `vite-plugin-pwa`.
- **Maskable + standard PNG icons** (192 / 512 / Apple touch) are generated from the
  mascot SVG by `scripts/gen-icons.mjs` (runs automatically before dev/build).
- A **service worker** (Workbox) precaches the app shell, the bundled CSS/JS, the
  PWA icons, and **all four alarm sounds**, and runtime-caches Google Fonts — so
  the whole timer (including alarms) works **fully offline** after the first visit.
- `registerType: 'autoUpdate'` keeps the installed app up to date in the background.
- Install it from the browser's "Install app" / "Add to Home Screen" prompt.
  (The service worker is disabled during `pnpm dev`; test it with `pnpm build && pnpm preview`.)

### Mobile
- **Responsive** down to ~320px: portrait stacks into a single card; **landscape
  phones** switch to a compact two-column layout (ring + controls side by side) so
  nothing scrolls off-screen. Settings open as a full-width sheet.
- Touch-tuned: no tap-highlight flash, no accidental double-tap zoom, and inputs
  use a 16px font so iOS Safari doesn't zoom on focus.
- Buttons that the platform can't honor are hidden/disabled instead of dead:
  **Picture-in-Picture** (no mobile browser support) and **Fullscreen** (absent on
  iOS Safari) are feature-detected. Notifications work on Android Chrome and on
  iOS only when tomo is installed to the home screen as a PWA.

## Picture-in-Picture (the key feature)

tomo uses the **[Document Picture-in-Picture API](https://developer.mozilla.org/en-US/docs/Web/API/Document_Picture-in-Picture_API)**
(`window.documentPictureInPicture.requestWindow(...)`) to open a **320×320 square**
floating window that stays on top of everything.

How it works (`src/hooks/usePip.ts` + `src/App.tsx`):

1. Clicking the PiP button calls `requestWindow({ width: 320, height: 320 })`.
2. The app's stylesheets (`<style>` / `<link rel="stylesheet">` and any adopted
   stylesheets) are **copied into the PiP window's document**, and its
   `data-theme` / `lang` attributes are synced — so the mini window looks
   identical and respects dark mode.
3. The compact timer is rendered into the PiP window via a **React portal**
   (`createPortal(... , pipWindow.document.body)`). Because it's the **same React
   tree**, state stays in sync **both ways** automatically: the countdown, mode,
   and Play/Pause + Skip controls in the PiP window and the main window always
   match, and an action in either affects the other.
4. Closing the PiP window (`pagehide`) restores the timer to the main window and
   updates the toggle state.

**Feature detection:** if `documentPictureInPicture` is unavailable the PiP button
is **disabled** with a tooltip explaining it needs a Chromium browser.

## When an interval ends

A single "time's up" event (`handleIntervalEnd` in `src/App.tsx`) fires everything
together, using only the web platform's reliable mechanisms:

1. **System notification** (Notifications API). Permission is requested on the
   **first Start** (a genuine user gesture), not on page load. Clicking the
   notification calls `window.focus()` to bring the tab forward.
2. **Best-effort `window.focus()`** — helps when the window is merely unfocused.
3. **Tab-title flashing** (`⏰ Time's up!` ↔ the normal title) until you return to
   the tab, which stops on `visibilitychange`.
4. **PiP alarm state** — when the mini window is open it **pulses/flashes** into an
   unmissable alarm view. Since PiP floats on top of everything, keeping it open is
   the most reliable always-visible alert when the main window is minimized.
5. **Manual fullscreen** toggle (Fullscreen API) for a prominent "alarm" view.

> ⚠️ **Platform caveats (intentional):**
> - The main browser window is **not** resized/moved — browsers block
>   `window.resizeTo`/`moveTo` on the main tab, so tomo doesn't attempt it.
> - **Fullscreen requires a recent user gesture** (transient activation), so it
>   **cannot be auto-triggered** by the timer callback. tomo offers a one-tap
>   fullscreen button / notification click instead — it never promises true
>   auto-maximize where the platform forbids it.
> - A background tab cannot force itself to the foreground; the notification click
>   is the reliable path back.

## Browser support

| Feature | Chrome / Edge 116+ | Firefox | Safari |
| --- | :---: | :---: | :---: |
| Timer, sounds, i18n, themes | ✅ | ✅ | ✅ |
| Install as PWA + offline | ✅ | ✅ | ✅ (Add to Home Screen) |
| Notifications | ✅ | ✅ | ✅ (PWA only on iOS) |
| Fullscreen | ✅ | ✅ | ✅ |
| **Document Picture-in-Picture** | ✅ | ❌ (button disabled) | ❌ (button disabled) |

The Document PiP path is the primary target; on unsupported browsers the rest of
the app works normally and the PiP button is disabled with an explanatory tooltip.
